关键结构与参数（可在新卡中微调以免越框）：

| 层或阶段 | 红塔实现 |
| --- | --- |
| 牌面尺寸与透视 | `card-orbit` 为 2:3、最大宽 445px；舞台 `perspective:1700px` |
| 牌背翻入 | `.card-rig` 的 `card-arrive`，2.25s，从 `rotateY(-175deg)` 到正面，略微过冲后停住 |
| 内景背景 | `.plate-art::before` 使用补全背景图、`scale(1.12)`，移动量为 `-7×depth` / `-6×depth` px |
| 主体前景 | `.tower-depth` 使用透明前景图、`translateZ(18px) scale(.78)`，移动量为 `10×depth` / `11×depth` px |
| 整牌随指针 | 水平约 ±21°、垂直约 ±16°，另有约 ±10/8px 平移；从整个 `stage` 接收鼠标位置 |
| 材质 | 前景复制层做同色轮廓光；掩膜扫光与牌面扫光随指针改变方向/位置，不能盖住主体结构 |
| 主题爆发 | 闪电 2.45s 开始，冲击光 2.55s 开始，碎片在后半段飞散；主体 `tower-breakout` 4.25s |
| 可交互定格 | 入场后 4.3s 设置 `data-ready=true`，显示文字与星级并允许视差；重播清理旧定时器、归零姿态、重启动画 |
| 文字与星级 | 七美德和幸运值是 `card-orbit` 的同级子元素，独立于 `tower-depth`；幸运星当日按日期哈希稳定 |

## 可复制给执行者的单卡提示词

> 请为我的 Cyber Arcana 牌组制作 **{编号 / 卡名}** 的独立网页卡牌动效。以当前工作区的 **{红塔原版页面路径}** 作为唯一已确认的运动与交互基准，先实际阅读它，不要修改红色「崩裂高塔」页面及其三张素材，也不要把这张新卡塞进通用 `tarot-deck.html` 版式。目标原画：**{目标原画路径}**；主要形态：**{主体}**；主色：**{色板}**；主题事件：**{事件描述}**。
>
> 先准备同一坐标系的 2:3 完整原画、补全主体遮挡区域的背景 PNG、透明主体 PNG；检查尺寸、透明通道和边缘配准。沿用红塔的牌背翻入 → 落位 → 主题事件 → 主体显现 → 定格的时间轴、场景纵深、牌框和文字层级、鼠标/触控视差、重播与低动态设置。仅替换与目标卡有关的视觉、配色和七美德文案。左上角是无实心背景的晶体质感美德标题、赠言和指引；右下角是六级颜色映射的「今日幸运值」。文字与牌框随整牌转动，主体单独做明显视差，背景轻微反向位移。主体始终在牌框内，终态不自动回转。
>
> 完成后构建页面，并在桌面及窄屏实际检查：开始、约 2.5 秒爆发、约 4.3 秒定格、鼠标移到四角、触摸拖动、重播、低动态模式。特别比较红塔的运动节奏、纵深与文字挂载方式。若素材不能配准，先说明缺什么，不要用单张平面图冒充立体卡。给我新卡的预览链接，并列出与红塔保持一致的部分和该卡独有的主题事件。

## 交付前的快速检查

1. 若提供了原版红塔文件，确认其未被误改；本项目可参考上面的哈希，其他项目以用户确认的版本为准。
2. 新卡前景与背景同尺寸；前景有真实透明区，主体从原画抠出而非整卡复制。
3. 全部指针极值下主体仍视觉上位于牌内，前后层边缘无明显破洞、重影或露出旧主体。
4. 每次重播关键帧、场景与镜头一致；只随机化设计允许的文案。星级当天稳定。
5. 牌框、晶体文字与幸运值只跟随整卡；主体独立位移，未带着文字一起晃。
6. 竖屏页面无主要内容裁切；低动态设置下文字与卡牌仍完整可见。
